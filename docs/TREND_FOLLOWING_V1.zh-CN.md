# 趋势跟踪 V1：规则、实施范围与验证

更新日期：2026-11-03，包含 v1.1.0 统一候选池、v1.1.1 平仓后等待新信号、v1.2.0 可选满仓换仓与当前源码 v1.3.0 断点恢复和候选详情；历史首版见 [v1.0.0 发布说明](releases/v1.0.0.md)。目标是响应已出现的趋势，允许向上做多、向下做空；不以历史暴涨推断未来下跌，不按最近交易盈亏自动调参。代码未连接账户进行实盘验证，尚无历史样本外绩效结论。

## 已实现的闭环

1. 全市场硬过滤，常规每小时更新。沿用当前合格标的规则，仍排除 BTC/ETH、稳定币、黄金代币和非加密标的；不是每个 USDT 合约都必定参与。
2. 所有合格品种进入统一候选池，取消评分、分组配额、排名淘汰与高分预留名额。多空权限来自用户勾选，实际方向由标的自身趋势与突破信号决定；持仓名额及风险预算继续限制新仓。
3. 用已收盘 EMA20/60、慢线三根斜率及快慢线分离度判断 Up / Down / Range；数据缺失为 Unknown。价格须位于快线的相应一侧。Range 包括横盘与尚未确认的转换阶段，不强行判方向。
4. 默认以信号 K 收盘突破其之前 12 根高低价通道，突破缓冲为 0.1ATR，收盘在本根振幅中的顺势位置至少 0.6。下一根用真实可用报价判断入场，价格须仍在边沿外且不超过 1.5ATR 追价限度。
5. 默认多头量比 1.5，空头不强制放量；可配置。慢跌不会因为归入某个名单而额外套用爆拉量比。
6. 以初始止损距离加费用/滑点估算反推数量，并受单笔名义上限约束。申请组合及同向计划风险预算，计入在途开仓。
7. 初始 ATR 止损、Chandelier 棘轮追踪、确认反向趋势离场；自动 bot 不立即反手。新仓闸门不阻止已有仓位平仓。

默认 signal 周期为 1h；15m、30m、2h、4h 可显式选择。不存在事后选择最赚钱周期或动态切换周期的算法。

## 平仓后再次入场（v1.1.1）

智能自动 bot 完全平仓后保留监控。以确认完全平仓的时刻计算，跳过平仓所在 K 线，等下一根完整 K 线收盘；该根或后续已收盘 K 线必须形成新的有效突破，才能再次申请入场。例如 1h 周期 13:20 平仓，14:00 只是下一根开始，最早在 15:00 检查 14:00–15:00 的收盘信号。时间到并不会自动开仓。

该限制独立于“每根最多一次”和首次入场的盘中/收盘选项，多空、止盈、止损均适用。再次入场的突破通道、ATR 和量比使用收盘确认口径，原趋势过滤及账户风险预算继续生效；发送异步订单前再次核对等待与确认条件。开仓拒绝或被风控拦住不会清掉等待。

等待时间戳 `reentry_after_ms` 随 GUI / headless 的 bot 状态落盘；恢复、模板替换、常规扫描及异动扫描均保留，实际开仓成交后才清除。等待中的记录不会自动删除；若不符合硬过滤或关闭智能模式，只暂停新仓并保留记录，防止删除后重新建 bot 绕过等待。手动明确删除 bot 属于丢弃该记录。

部分平仓继续保护剩余仓位，完全平仓才开始等待。正常识别的交易所保护止损也记录等待；对账异常仍沿用原有停止核对规则。状态仍使用现有保存机制，正常保存后重启可恢复；未落盘前的突发断电不具备逐订单日志保证。

## 满仓换仓（v1.2.0，可选）

GUI 在“智能模式设置 → 风控 → 智能持仓”勾选“满仓换仓”；headless 使用 `smart_mode.rotate_when_full: true`。默认关闭，旧配置保持关闭。只有智能模式启用、持仓上限大于 0、自动 bot 启用 EMA 趋势过滤时生效。关闭开关会取消尚未发出的主动换仓；已提交的平仓需要等回执，之后不再为该任务开新仓。

新候选须通过硬过滤及全部入场条件，且具有仍有效的收盘突破和原方向趋势许可。即使首次入场设置为盘中突破，也独立计算收盘模型：ATR、通道和量比使用突破前参考窗口，不改变普通未满仓入场模式。有效期止于下一次 K 线切换，快照与报价还必须足够新鲜。队列按有效申请实际到达的顺序处理；预检未通过的申请重新评估时排到队尾，避免堵住其他可执行信号。旧证据过期即丢弃，不补历史漏单，不引入评分或多空榜。

旧仓只限正常运行的自动趋势仓，需至少观察到开仓后的 6 根连续完整 K 线、连续 3 根失去原方向趋势许可；最新收盘在快 EMA 不利一侧，多仓低于快线、空仓高于快线；最近 3 根没有刷新观察到的持仓有利收盘极值。优先原方向许可失效时间最长，其次开仓更早，最后按品种名稳定打破并列。止损、反转、假突破等正常退出优先，不以浮盈亏大小选择牺牲仓位。手动仓、暂停仓、委托在途或对账异常仓不参与替换。

确认计数按不同的已收盘 K 线累计，重复轮询不增加。v1.3.0 起，已确认计数、有利收盘极值及最后处理位置会落盘；缺失 K 线或无效响应保留断点，等待按时间顺序补齐。重启不清零计数，也不会直接把离线时长当作失效证据。用户实际改变趋势模型参数时，才按新参数重建对应观察。开仓时间未知或历史数据不完整的仓位不自动替换。

没有每日次数或额外换仓间隔限制。独立新信号可以在同一周期连续申请，执行时仅保留一个换仓任务，避免抢占名额。一个新信号已经尝试主动平仓后，不会使用同一根 K 线的证据继续牺牲其他持仓；失败等待独立的新信号。

流程为：预检新仓数量和初始止损 → 假设释放目标旧仓后检查持仓数、保证金、组合与同向风险、含成本的当日亏损 → 平仓前复核 → 完全平仓 → 重验当前信号与所有预算 → 开仓。若自然退出已释放空位，取消主动平仓；如果释放一个旧仓仍不足以满足上限，则不平旧仓。平仓失败、部分成交、结果不明不触发新仓。旧仓完全退出后新信号失效、暂停或风险限制变化时保持空位。换仓新仓同样挂原有保护止损，旧币继续执行 v1.1.1 的再次入场等待。

任务和待申请队列不跨重启续发。仅预留名额尚未发单时，不把恢复后的候选误标为未知开仓；一旦开始提交真实开仓，继续使用原有未知委托和预算预留规则。周期保存仍不构成逐订单写前日志，启动对账不可跳过。

## 断点续监控与候选详情（v1.3.0）

无需另开开关。GUI 继续使用原数据目录中的 `sar_bots.json`；headless 继续使用 `<state_path>.sar`。不要在全新的空数据目录启动并期待读取旧断点。状态写入使用临时文件与原子替换；文件损坏时保留原文件并停止恢复，避免静默清零。

- **保存什么**：原有持仓、初始/移动止损、持仓极值、冷却、平仓后等待，加上换仓完整观察根数、连续失效根数、有利收盘极值及时间、已处理收盘游标、同根换仓尝试记录、入场准备状态、自动品种实际趋势参数、趋势变化和最近 40 条事件。
- **恢复顺序**：读取保存状态 → 获取新鲜仓位/委托结果 → 按收盘时间补齐历史 → 更新当前行情 → 通过当前候选过滤和风险闸门后参与交易。两项核对未完成时不开新仓；已有止损保护继续保留。
- **补齐方式**：每次最多补 256 根缺失收盘记录，继续沿用正常行情刷新节奏。每根使用当时可见的固定长度窗口计算，不拿后来的行情回填过去。重复记录不重复计数；中间有趋势恢复会正确清除连续失效计数。
- **周期切换**：行情时间与请求签名的安全偏移分开计算，请求跨整点时按响应后的行情时间校验。暂缺新 K 线显示“等待新K线 · 保留进度”，按 3、6、12 秒间隔最多快速重试三次；重试受现有刷新任务和接口限流约束。仍未恢复则汇总告警，回到正常刷新频率。主日志汇总等待、持续异常和实际恢复，具体原因留在候选详情。等待期间不开新仓，不清空监控计数或止损；实时价格仍检查已有止损线，交易所硬止损继续保留。
- **边界**：补齐用于接续监控和观察计数，不补发历史开平仓单，也不假造离线成交或盘中极值。实际持仓、委托或保护单出现差异时仍走对账流程。首次升级没有监控断点时，会尝试用开仓后的历史 K 线重建；拿不到完整历史则保留等待状态。周期保存不等同于逐订单写前日志。

“智能模式设置 → 统一候选 · 监控详情”每 2 秒刷新，包含最新候选，以及仍在持仓、恢复或等待再入场的自动品种。支持品种搜索和有信号、入场受阻、持仓中、可被替换、等待再入场、数据异常筛选。未连接时显示保存值并标注离线。

| 表格/详情 | 含义 |
|---|---|
| 当前阶段 | 等待趋势、等待突破/收盘、受阻、在途委托、持仓、平仓后监控、恢复或停止 |
| 最近趋势 | 已确认的上涨/下跌/震荡过渡、连续观察根数、前态和转换时间；不是预测 |
| 形态描述 | 通道内整理、盘中突破、收盘突破确认；盘中信息与收盘证据分别标明 |
| 条件依据 | EMA、斜率、间距、收盘位置、通道、ATR、箱体/效率比、量比、追价距离，以及当前门槛 |
| 持仓 | 方向、持有时长、按最新报价估算的浮盈亏/R、初始与移动止损、硬止损委托 |
| 换仓 | 保留/候选/执行状态；6 根完整持仓观察、3 根失效、3 根有利极值保护的实际进度；近期换仓理由和结果 |
| 再入场 | 最早新信号确认时间和剩余根数；到期后仍须有新的收盘突破 |
| 数据与事件 | 已处理收盘、补齐目标、剩余根数、更新时间、信号有效边界、恢复/趋势/执行事件 |

“可被替换”表示旧仓符合观察条件，仍需有有效新信号、满仓状态和释放后足够的风险预算才会执行。条件面板不增加评分、不改变入场和退出算法；最终数量取整、保证金及风险预算仍以下单前复核结果为准。

## 因果与时序约定

`src/core/trend_following.h` 是纯计算层，GUI 与 headless 使用同一份结果。

- 输入包含末尾未收盘 K 线，但它不参与趋势确认。
- 收盘突破的通道及参考 ATR 同时排除当前未收盘根和信号根。大阳线、大阴线不能撑大自己的风险分母。
- 趋势许可可使用刚收完的信号 K，因交易发生在它收盘之后。
- 新模型使用传统高低价 Donchian；手动旧模型继续使用原实体通道，便于明确基准差异。
- 可显式关闭 `tf_close_confirm` 使用盘中突破。该模式仍需已收盘趋势许可，通道和 ATR 排除未收盘根；量比可按原有时间折算规则处理。
- 收盘确认只在紧随信号的当前 K 线内有效。HTTP 成功不等于数据有效：K 线时间缺口、未来时间、当前根滞后、配置不一致都会拒绝新信号。
- 快照过期后停止新增仓位，既有止损仍可执行。提交订单前再检查当前信号、追价位置、报价变化及预算。
- 每根最多一次入场。确认失败或触及止损后，须等待后续有效信号，不立即翻方向追单。

关闭 `tf_enabled` 可用于旧规则对照。新的模型默认关闭箱体宽度硬过滤和盈利加速收紧；原有开关仍保留，避免未经比较就把所有过滤、退出条件叠加。

## 异动唤醒

`src/core/market_wake.h` 比较相邻成功轻量观察的价格，默认每 60 秒一次。若某个已在上次合格集合中的币变化达到 `max(2 × 上次完整扫描的 ATR%, 1%)`，允许一次全市场重扫，默认冷却 300 秒。上涨和下跌对称处理，同批事件合并。

异常分母来自事件前的扫描。首次观察只建立基线；数据中断超过 2.5 个观察周期重新建立基线，不把断流期间的累计变动当成刚发生的事件。事件扫描可以加入候选、暂停明确不合格品种的新仓；移除留给常规扫描，且不推迟正常小时扫描。

这不是秒级抢单功能：当前沿用 REST 与固定周期 K 线；新上市、未过门槛或上次没有 ATR 的标的等待常规扫描。默认收盘模式可能错过短促插针。盘中模式是另一项显式实验选项，异动本身不越过趋势过滤、追价或风险预算。

## 组合预算与未知委托

默认研究初值：单笔风险 1U、单笔名义上限 100U、组合 6U、同向 4U、成本估算 20bps。它们不依据账户净值自动调整，需要按账户规模配置。

```text
计划数量 = min(单笔名义上限 / 预计成交价,
               单笔风险 / (初始止损距离 + 预计成交价 × 成本率))
预留风险 = 向下取整后的数量 × (初始止损距离 + 预计成交价 × 成本率)
```

所有币同向共用预算，作为保守的共同风险约束；尚未实现动态相关系数矩阵或行业分组。组合预算同时覆盖手动与自动 bot；初始已承诺风险保留到减仓/平仓，不把浮盈当成可立即循环借用的预算。估算成本不包括未来持有期资金费，也不能限制跳价、滑点和保护失效下的真实亏损。

开仓发送前在引擎锁内核对并预留预算，随后才发送订单。已知拒单和终态零成交释放预留。超时、非终态响应或发送阶段异常保持预留并停止该 bot，同时阻止进一步开仓；平仓路径继续工作。

已知 clientOrderId 的未知订单每分钟最多查询一次。只有原委托已确认终态或明确不存在，并且之后两次新鲜仓位快照均为空，才释放预留；该 bot 保持暂停，其他候选可恢复。仅有空仓快照、等待时间过去或点击恢复，不会绕过未知委托。若交易所有实际仓位，继续告警并冻结新风险，需先处理/核对该仓位。极端异常没有取得 clientOrderId 时不猜测终态，需要人工核对。

预留、未知状态与 clientOrderId 随 bot 状态落盘；关闭智能模式也不会丢弃未知开仓。未知 bot 不允许被当空仓自动淘汰或替换。持久化依然采用现有周期保存机制，尚未引入逐订单写前日志；突发断电仍需启动对账发现未跟踪仓位。

交易所灾难止损冻结在开仓时的初始保护位置，并不跟随本地移动止损。停机期间不保证保住已形成的浮盈。

## 配置和迁移

新字段位于 `smart_mode` 与 `smart_mode.template`，完整字段表见 [Headless](HEADLESS.md)。GUI 智能设置页支持均线、斜率、分离度、确认模式、空头量比和组合预算，使用相同 JSON 校验。事件观察参数可在配置中修改。

旧文件保留显式配置的仓位和已有过滤参数，新字段缺省时采用 V1 默认。`weak_vol_ratio` 迁移为全体空头的 `tf_short_vol_ratio`，新字段优先；新保存不再输出旧字段。`turtle` 输入别名继续兼容，输出为 `trend_following`。旧评分、分榜、候选配额和排名淘汰配置会被忽略，新保存不再输出；旧评分元数据不再读取或记录。旧 K / V 策略标记仅用于拒绝不兼容持仓恢复。

候选为空是合法结果；明确不合格的旧候选暂停新仓。保留原有门槛滞回：池内成交额下限为配置值的 80%，ATR 区间向外放宽 20%，涨跌幅与资金费率上限只约束新加入。数据未知时保留原状态。一次大批不合格时保留 bot 待复核，但禁止它们新开仓。持仓、在途订单与已停止的 bot 不自动移除。重启恢复的自动 bot 必须再次通过过滤才能新开仓。

已有持仓的开仓价、数量和止损状态保留；保护线保持棘轮。修改趋势模型的出场条件可能改变之后的持仓退出时机，升级不能解释为交易行为完全不变。

## 中文品种拉取失败修复（v1.3.1）

中文名称合约的单品种请求原先直接拼接 UTF-8 名称。v1.3.1 对参数值进行百分号编码，再组成请求和计算签名，覆盖K线、交易精度、查单、开平仓、杠杆、保护止损、持仓量和资金费接口。英文品种的原有参数保持相同。参考 [libcurl 参数编码说明](https://curl.se/libcurl/c/curl_easy_escape.html)。

“价格在更新”不代表“K线信号可用”：价格轮询读取全市场数据，K线按品种请求。现在拉取失败会显示“K线数据异常”，悬停或候选详情能看到具体接口错误；历史补齐和仓位核对另行显示。“已移出候选”不再盖住获取失败原因。网络恢复后按原断点续接，不需修改趋势参数或清除数据。首次未形成有效快照的品种仍须先取得完整预热K线。

## 杠杆确认超时恢复

每次入场仍重新确认目标杠杆，不使用长期缓存。设置超时、连接中断或网关故障时，先按品种查询交易所实际倍数；空仓记录也可用于确认，多空持仓记录必须一致。采用 [USD-M Position Information V2](https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/Position-Information-V2) 和 [Portfolio Margin Query UM Position Information](https://developers.binance.com/docs/derivatives/portfolio-margin/account/Query-UM-Position-Information) 中的 `leverage` 字段，不从仓位保证金反推，也不把查询失败解释为默认倍数。

实际倍数等于目标时继续入场复核；仍无法确认才再设置一次，第二次仍超时再查询一次。一轮最多两次设置、两次查询。明确的参数、权限或限流拒绝不在本轮重复设置。确认失败后该品种等待 30 秒再按当前信号评估，连续失败不重复打印同一条告警；失败不消耗本根K线的入场资格。

确认杠杆不代表立即下单：重新读取最新价格、ATR和止损，重新计算数量，并检查趋势许可、突破、追价、信号/报价时效、再入场等待、暂停状态、组合保护及风险预算。数量取整可能涉及网络请求，因此发送订单前再检查一遍。已失效的旧信号不会排队补单。重试仅适用于设置杠杆，不重发开仓订单；已有持仓的平仓与硬止损保护继续沿原逻辑执行。
