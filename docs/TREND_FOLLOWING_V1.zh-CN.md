# 趋势跟踪 V1：规则、实施范围与验证

日期：2026-10-31。目标是响应已出现的趋势，允许向上做多、向下做空；不以历史暴涨推断未来下跌，不按最近交易盈亏自动调参。代码未连接账户进行实盘验证，尚无历史样本外绩效结论。

## 已实现的闭环

1. 全市场候选筛选与评分，常规每小时更新。沿用当前合格标的规则，仍排除 BTC/ETH、稳定币、黄金代币和非加密标的；不是每个 USDT 合约都必定参与。
2. 分组仅用于排序和展示。所有分组的多空权限均来自用户勾选；实际方向由标的自身趋势决定。
3. 用已收盘 EMA20/60、慢线三根斜率及快慢线分离度判断 Up / Down / Range；数据缺失为 Unknown。价格须位于快线的相应一侧。Range 包括横盘与尚未确认的转换阶段，不强行判方向。
4. 默认以信号 K 收盘突破其之前 12 根高低价通道，突破缓冲为 0.1ATR，收盘在本根振幅中的顺势位置至少 0.6。下一根用真实可用报价判断入场，价格须仍在边沿外且不超过 1.5ATR 追价限度。
5. 默认多头量比 1.5，空头不强制放量；可配置。慢跌不会因为归入某个名单而额外套用爆拉量比。
6. 以初始止损距离加费用/滑点估算反推数量，并受单笔名义上限约束。申请组合及同向计划风险预算，计入在途开仓。
7. 初始 ATR 止损、Chandelier 棘轮追踪、确认反向趋势离场；自动 bot 不立即反手。新仓闸门不阻止已有仓位平仓。

默认 signal 周期为 1h；15m、30m、2h、4h 可显式选择。不存在事后选择最赚钱周期或动态切换周期的算法。

## 因果与时序约定

`src/core/trend_following.h` 是纯计算层，GUI 与 headless 使用同一份结果。

- 输入包含末尾未收盘 K 线，但它不参与趋势确认。
- 收盘突破的通道及参考 ATR 同时排除当前未收盘根和信号根。大阳线、大阴线不能撑大自己的风险分母。
- 趋势许可可使用刚收完的信号 K，因交易发生在它收盘之后。
- 新模型使用传统高低价 Donchian；手动旧模型继续使用原实体通道，便于明确基准差异。
- 可显式关闭 `tf_close_confirm` 使用盘中突破。该模式仍需已收盘趋势许可，通道和 ATR 排除未收盘根；量比可按原有时间折算规则处理。
- 收盘确认只在紧随信号的当前 K 线内有效。HTTP 成功不等于数据有效：K 线时间缺口、未来时间、当前根滞后、配置不一致都会拒绝新信号。
- 快照过期后停止新增仓位，既有止损仍可执行。提交订单前再检查当前信号、追价位置、报价变化及预算。
- 每根最多一次入场。确认失败或触及止损后，须等待后续有效信号，不立即翻方向追单。

关闭 `tf_enabled` 可用于旧规则对照。新的模型默认关闭箱体宽度硬过滤和盈利加速收紧；原有开关仍保留，避免未经比较就把所有过滤、退出条件叠加。

## 异动唤醒

`src/core/market_wake.h` 比较相邻成功轻量观察的价格，默认每 60 秒一次。若某个已在上次合格集合中的币变化达到 `max(2 × 上次完整扫描的 ATR%, 1%)`，允许一次全市场重扫，默认冷却 300 秒。上涨和下跌对称处理，同批事件合并。

异常分母来自事件前的扫描。首次观察只建立基线；数据中断超过 2.5 个观察周期重新建立基线，不把断流期间的累计变动当成刚发生的事件。事件扫描不推进正常按小时累计的淘汰计数，也不推迟正常小时扫描。

这不是秒级抢单功能：当前沿用 REST 与固定周期 K 线；新上市、未过门槛或上次没有 ATR 的标的等待常规扫描。默认收盘模式可能错过短促插针。盘中模式是另一项显式实验选项，异动本身不越过趋势过滤、追价或风险预算。

## 组合预算与未知委托

默认研究初值：单笔风险 1U、单笔名义上限 100U、组合 6U、同向 4U、成本估算 20bps。它们不依据账户净值自动调整，需要按账户规模配置。

```text
计划数量 = min(单笔名义上限 / 预计成交价,
               单笔风险 / (初始止损距离 + 预计成交价 × 成本率))
预留风险 = 向下取整后的数量 × (初始止损距离 + 预计成交价 × 成本率)
```

所有币同向共用预算，作为保守的共同风险约束；尚未实现动态相关系数矩阵或行业分组。组合预算同时覆盖手动与自动 bot；初始已承诺风险保留到减仓/平仓，不把浮盈当成可立即循环借用的预算。估算成本不包括未来持有期资金费，也不能限制跳价、滑点和保护失效下的真实亏损。

开仓发送前在引擎锁内核对并预留预算，随后才发送订单。已知拒单和终态零成交释放预留。超时、非终态响应或发送阶段异常保持预留并停止该 bot，同时阻止进一步开仓；平仓路径继续工作。

已知 clientOrderId 的未知订单每分钟最多查询一次。只有原委托已确认终态或明确不存在，并且之后两次新鲜仓位快照均为空，才释放预留；该 bot 保持暂停，其他候选可恢复。仅有空仓快照、等待时间过去或点击恢复，不会绕过未知委托。若交易所有实际仓位，继续告警并冻结新风险，需先处理/核对该仓位。极端异常没有取得 clientOrderId 时不猜测终态，需要人工核对。

预留、未知状态与 clientOrderId 随 bot 状态落盘；关闭智能模式也不会丢弃未知开仓。未知 bot 不允许被当空仓自动淘汰或替换。持久化依然采用现有周期保存机制，尚未引入逐订单写前日志；突发断电仍需启动对账发现未跟踪仓位。

交易所灾难止损冻结在开仓时的初始保护位置，并不跟随本地移动止损。停机期间不保证保住已形成的浮盈。

## 配置和迁移

新字段位于 `smart_mode` 与 `smart_mode.template`，完整字段表见 [Headless](HEADLESS.md)。GUI 智能设置页支持均线、斜率、分离度、确认模式、空头量比和组合预算，使用相同 JSON 校验。事件观察参数可在配置中修改。

旧文件保留显式配置的仓位和已有过滤参数，新字段缺省时采用 V1 默认。`weak_vol_ratio` 迁移为全体空头的 `tf_short_vol_ratio`，新字段优先；新保存不再输出旧字段。`turtle` 输入别名继续兼容，输出为 `trend_following`。旧分组码继续用于持仓记录，但不再强制交易方向。

已有持仓的开仓价、数量和止损状态保留；保护线保持棘轮。修改趋势模型的出场条件可能改变之后的持仓退出时机，升级不能解释为交易行为完全不变。

## 验证与后续研究

此次增加的确定性场景覆盖：上涨/下跌/横盘、未收盘插针不污染指标、信号根不扩大自身 ATR、长影线确认失败、追价与失效突破、独立空头量比、确认反转退出、断流仍能止损、多币交错下单、组合和同向预算、未知回执、终态查询、状态恢复与淘汰保护。

本地验证：Windows / GCC 16.2，Release，`CCBOT_WERROR=ON`，GUI 与 headless 均编译成功；CTest 17/17 通过（约 24.5 秒），测试套件登记检查和 `git diff --check` 通过。最终日志位于本机忽略目录 `build/upgrade-build-audit.log`、`build/upgrade-tests-audit.log`。未运行实盘下单、真实账户恢复或跨平台 sanitizer；假 HTTP 测试覆盖普通合约及 Portfolio Margin 查单路由。

这些测试验证规则和执行契约，不验证盈利。尚未实施的研究模块包括：独立回踩恢复入场、道氏摆动结构、ADX 对照、盘口点差/深度硬准入、市场广度与动态相关组，以及完整四级账户风险状态机。OI 与主动成交仍为观察数据，未加入新的强制因子。

下一阶段应使用时间顺序历史回放与未参与选参的样本外数据，计入手续费、资金费、滑点、下架和可交易历史集合，比较旧规则、V1 收盘模式及固定短周期版本。报告收益之外，还需报告回撤、连续亏损、漏掉的大行情与退出回吐。当前没有可报告的历史收益率或黑天鹅盈利概率。

订单核对复用了按账户模式选择的接口：[USD-M Query Order](https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/Query-Order)、[Portfolio Margin Query UM Order](https://developers.binance.com/docs/derivatives/portfolio-margin/trade/Query-UM-Order)。
