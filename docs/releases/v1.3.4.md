# v1.3.4 — 中文合约行情修复与 macOS 同目录数据

修复系统字符环境可能破坏中文合约 UTF-8 名称、导致部分品种持续无行情的问题，并将 macOS 桌面运行数据统一到 `TradingBot.app` 同级的 `data/`。

## 中文合约与行情提示

- 品种名称仅将 ASCII 英文字母转换为大写，保留中文 UTF-8 字节。行情订阅、缓存、GUI 添加与黑名单、headless 配置与恢复采用一致处理。
- 拒绝损坏的 UTF-8 和替代字符；已有乱码存档在恢复前报错并保留原文件，不猜测真实品种、不删除仓位或监控记录。此时本地策略尚未启动；该检查不会撤销交易所已有硬止损。
- 行情提示区分部分品种异常、全部品种异常、连续请求失败及拉取中断。悬浮详情显示具体品种和报价更新时间，便于定位“200 个品种中 3 个异常”等情况。
- 行情可用性检查统一处理过期、未来、非正数与非有限报价。有效报价品种仍受各自信号及风控闸门约束，整体黄色提示本身不是全账户开仓开关。
- 附 `tools/repair_symbol_state.py` 离线辅助工具：默认只报告；在完整持仓与委托快照核对后，仅为唯一匹配、空仓且没有未决委托的记录生成待审核副本与备份。拒绝歧义、重复、持仓或未知状态，原文件不覆盖。详见 [中文存档恢复说明](../SYMBOL_RECOVERY.zh-CN.md)。

## macOS 数据目录与升级

- 配置、持仓及监控断点、日志、journal 等统一保存在 `.app` 同级的 `data/`，运行时不写入新的应用包内部。API 凭证仍保存在系统钥匙串，复制 `data/` 不会导出钥匙串。
- 首次升级且同级 `data/` 不存在或为空时，优先复制本应用包内旧 `Contents/MacOS/data/`；没有该目录时复制原 Qt AppData 目录，通常为 `~/Library/Application Support/CCGMonitor/TradingBot`。原目录完整保留。
- 全部文件复制到暂存目录后整体启用；源目录正在使用、不可读、复制失败或存在链接/特殊文件时停止启动。已有非空 `data/` 直接使用，不混合多个目录的数据。
- 程序旁目录不可写时明确报错。数据目录和迁移源使用文件锁，避免同时运行两个实例覆盖断点。headless 继续使用配置指定的数据路径。

升级前关闭旧程序、备份完整数据，在可写文件夹中解压新版。若实际使用的数据在另一个旧 `.app` 内或另一个便携文件夹中，先将完整 `data/` 复制到新版 `.app` 同级。不要只复制日志或部分 JSON。启动后核对持仓、止损保护、行情和监控进度；已有乱码按恢复说明处理，勿通过删除整个数据目录消除提示。

Windows 保留原有便携数据行为。macOS 运行基线为 15.0，按 Intel / Apple Silicon 选包；应用使用临时签名，未做 Apple Developer ID 公证。Linux 包为 headless，以 Ubuntu 24.04 为基线。详见 [平台说明](../PLATFORMS.zh-CN.md)。

## 回归与发布验证

新增覆盖中文名称与非 ASCII 字节、不同字符环境、部分行情异常、损坏存档拒绝、旧存档核对工具，以及 macOS 新建目录、完整迁移、原目录保留、已有数据优先、旧包目录优先、并发锁、迁移失败与链接拒绝等场景。

发布要求同一提交的 Windows x64、macOS Intel / Apple Silicon、Linux x64 / ARM64 原生 CI，以及 ASan/UBSan、TSan 全部通过。桌面平台各 18 套 CTest，Linux 各 17 套；三个构建流水线另运行 4 项离线恢复工具测试。所有委托回归使用模拟接口，不连接实盘账户。

最终提交、CI 链接及附件校验记录见 GitHub Release 和 `BUILD_VERIFICATION.json`。各平台包均包含 `BUILD_INFO.json`、依赖清单、文档和许可证，使用 `SHA256SUMS.txt` 核验下载。
