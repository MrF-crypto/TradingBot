# v1.3.5 — macOS 首次启动与全新配置

修复下载后的应用在只读临时目录运行时无法启动的问题，取消手动创建占位文件、迁移目录和清理钥匙串的要求。

- 正常运行优先使用 `.app` 同级 `data/`；首次启动处于 AppTranslocation 或程序旁不可写时，自动使用 `~/TradingBot/data`。记住实际数据位置，后续启动及应用移动继续使用同一份数据。已有同级数据仍优先，不把不可读或缺失的旧数据当成新账户。
- 首次发现旧数据时提供“全新配置”和“恢复旧数据”。全新配置直接打开 API 设置，旧数据和旧凭证保留；恢复则完整复制旧数据，并保留断点与原目录。
- 全新配置拥有独立、持久的钥匙串身份，避免读取旧 API 或覆盖旧配置的凭证。退出后尚未填写 API 的配置，下次仍进入设置，不自动连接旧账户。
- 设置中新增“打开数据文件夹”，无需通过终端寻找日志或备份位置。备份时保留完整 `data/`，包括新配置的 `.tradingbot-profile.json`。
- 已有数据仍采用文件锁和原子迁移。全新配置不能覆盖已有数据；配置身份损坏、记忆目录缺失或已有数据不可写时停止账户加载。

全新配置只建立新的本地配置，不会平仓、撤销交易所委托或自动接管旧仓位。旧配置恢复流程和 Windows、headless 的数据路径行为保持兼容。

回归覆盖启动选择、无旧数据安装、只读临时路径、实际目录记忆、重启凭证隔离、旧数据保留、损坏身份拒绝及已有数据不覆盖。macOS 钥匙串测试使用独立测试条目并清理，不写入用户原有的 API 条目。平台要求与升级方式见 [平台说明](../PLATFORMS.zh-CN.md)，最终构建结果以对应 CI 为准。
