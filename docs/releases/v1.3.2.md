# v1.3.2 — 审计修复与跨平台构建

本版本在原生 CI 和包检查通过后发布。对应 [2026-11-03 审计](../AUDIT_2026-11-03.zh-CN.md) 的 7 项问题，策略的趋势许可、突破方向、止损、再入场等待和满仓换仓规则保持原有配置。

## 相比 v1.0.0 的功能更新

- 智能模式使用统一候选池，移除多空评分名单；通过过滤后由实际突破决定方向。
- 平仓后保留监控，等待下一根完整 K 线收盘确认新的突破；可选满仓换仓，旧仓失效与新信号均需满足规则。
- 监控断点记录趋势、换仓计数、止损极值和再入场等待；重启或网络恢复后补齐缺失数据，不直接重放历史订单。
- 候选列表增加趋势、形态、入场阻拦原因、换仓理由及恢复进度；修复中文名称合约的 UTF-8 请求参数编码。

## 执行与恢复修复

1. 合法 JSON 中的 `-1006/-1007/-1000` 和 HTTP 503 执行未知消息进入原订单查单流程，未确认终态时保留风险预留，避免当成普通失败重开。
2. 平仓返回 `-2022` 后重新查询对应方向的实际持仓。未确认空仓时保留本地跟踪和保护；硬止损须核对条件单及其实际订单的成交终态，并按真实成交均价记账。空仓但找不到可核实成交时停止该 bot，明确提示成交和盈亏待核对。
3. headless 在取得保存锁后才读取引擎快照，串行完成序列化、写入和替换。GUI、headless 与智能状态使用独立临时文件、完整写入、刷新及原子替换；写入失败保留旧有效文件。
4. 退出先关闭数据任务入口，等待数据任务结束，再关闭并排空订单池。两个池的结果共同决定能否析构；超时路径保存快照后终止进程，避免后台任务继续访问已销毁的对象。
5. 每次新开仓都确认杠杆设置响应中的实际值，取消依赖旧成功缓存；未确认目标杠杆则取消新开仓。
6. 普通入场与换仓都在实际下单前检查报价时间；报价超过 15 秒或时间异常则等待下一次有效报价。
7. 断点或智能状态保存失败会记录具体原因、暂停新增风险；已有持仓仍可止损和平仓。各保存组件独立恢复，不能互相清除错误；手动暂停也不会被自动恢复覆盖。首次入场前先检查断点能否保存。

新增回归覆盖两种账户的 JSON 状态未知、拒绝平仓与真实硬止损成交、失败杠杆、排队报价过期、并发保存、UTF-8 路径、保存失败恢复和双线程池关停。原来通过“保护单从活跃列表消失”推断成交的接口已删除。

## 平台与升级

Windows x64 保留桌面版和 headless。macOS 增加 `.app` 打包、Intel / Apple Silicon 原生构建、依赖和离线启动检查；Linux 配置 x64 / ARM64 headless 构建。详细命令、数据目录和系统版本见 [平台说明](../PLATFORMS.zh-CN.md)。不包含 iPhone/iPad。

保留 v1.3.0/v1.3.1 状态格式兼容，新增的消失保护单编号字段用于后续成交核对。升级前停止旧进程并保留完整数据目录；启动后的对账完成前仍不会直接重放历史信号。

## 验证记录

- Windows x64：GCC 16.2 / Qt 6.12，Release、警告视为错误；18/18 CTest 通过，29.24 秒。随后补充的生产保存入口回归及调整后的 Qt 测试入口也单独通过。
- Linux x64：本机 WSL Ubuntu 24.04，GCC 13.3、CMake 3.28、系统开发库，Release、警告视为错误；17/17 CTest 通过，30.62 秒；headless `--version` 离线启动通过。这是系统依赖构建，不是静态 vcpkg 便携发布包。
- Linux 线程池与双池关停测试：ASan + UBSan（含泄漏检测）通过。TSan 首次运行在测试启动前出现 WSL `unexpected memory mapping`；仅对此测试进程使用 `setarch x86_64 -R` 后通过，退出码为 0，没有更改系统全局设置。上述结果限于线程池及关停套件，不代表整个应用的 sanitizer 验证。
- 4 个 workflow YAML 解析通过；套件登记检查通过（ASan 17、TSan 7）；应用包白名单夹具能放行必要元数据，并拒绝凭证和状态文件；`git diff --check` 无空白错误。
- macOS Intel / Apple Silicon、Linux ARM64：已配置原生构建、测试和打包检查，本机未执行。完整 ASan/TSan 矩阵需 CI 执行后另行确认。

所有委托测试使用模拟客户端，没有连接真实账户或发送真实订单。发布包内的 `BUILD_INFO.json` 记录确切源码提交和原生 CI 链接，`DEPENDENCIES.json` 记录依赖版本；最终发布验证结果见 GitHub Release。
