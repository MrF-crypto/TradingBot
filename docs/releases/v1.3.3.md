# v1.3.3 — K 线周期切换与刷新修复

针对整点大量出现“K线未到目标时间”、等待下一分钟才重试及逐品种日志刷屏的问题，统一修复桌面版与 headless 的行情校验和刷新调度。

## 主要变化

- 行情时间与签名请求的 1 秒安全偏移分开计算，避免整点首秒把有效新 K 线判为异常。请求排队或 HTTP 响应跨越周期时，按响应后的行情时间校验；历史补齐仍使用固定分页边界。
- 新 K 线暂未返回时，按 3、6、12 秒间隔最多快速重试三次，受现有任务队列和接口限流约束。仍未恢复则回到正常刷新频率；整点前刚刷新成功，也会及时调度下一周期的数据。
- 主日志按批次汇总等待、持续异常和实际恢复，避免每个品种、每次重试重复刷屏。真实网络或数据错误连续发生时仍告警；候选详情保留各品种的具体原因。
- 候选面板区分“等待新K线 · 保留进度”和持续数据异常。未参与本轮刷新或仅补齐历史的品种，不会被错误报告为行情已经恢复。

## 断点与持仓保护

等待期间暂停受影响品种的新开仓，以及依赖新指标的止损推进；监控游标、趋势观察和换仓计数、持仓与已有止损线继续保留。实时价格仍检查已有止损线，K 线暂缺不会撤销交易所硬止损。恢复后按原断点补齐并去重，不重放历史交易。

刷新重试状态只在内存中保存，不改变持久化断点格式；兼容已有状态。升级时停止旧进程并保留完整数据目录，新进程先完成对账与行情补齐。

## 回归与发布验证

- Windows 本地：桌面版与 headless 在 Release / 警告视为错误配置下编译通过，18/18 CTest 通过。
- Linux x64 本地：WSL Ubuntu 24.04 的 headless 构建通过，17/17 CTest 通过。
- 新增回归覆盖整点首秒、请求及计算跨周期、旧数据/未来数据/缺口拒绝、有限重试、160 个候选的日志汇总、并发刷新、等待期间多空止损、禁止旧信号开仓及等待中重启恢复。

正式发布要求 Windows x64、macOS Intel / Apple Silicon、Linux x64 / ARM64 的原生 CI，以及 ASan/UBSan、TSan 全部通过。最终提交、运行链接和附件核验结果记录于 GitHub Release 及 `BUILD_VERIFICATION.json`；每个包包含 `BUILD_INFO.json` 和依赖清单。

Windows 与 macOS 包含桌面版和 headless，Linux 提供 headless。macOS 运行基线为 15.0，应用使用临时签名，未做 Apple Developer ID 公证；Linux 以 Ubuntu 24.04 为构建基线。详见 [平台说明](../PLATFORMS.zh-CN.md)。所有委托回归使用模拟接口。
