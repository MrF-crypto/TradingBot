# TradingBot v1.4.3 发布前代码审查

审查基线：v1.4.2（`a32791a8bc1326b583c18b7c9592ffa2e5fda194`）及工作区的杠杆超时恢复补丁。范围包括开平仓确认、异步等待后的入场检查、利润归集、断点写入和退出顺序、依赖调用关系以及五个平台发布包门禁。实盘目录和账户未用于测试或修改。

## 发现并修复的问题

1. **开仓意图保存期间条件改变后仍下单。** 入场计划在保存账本前完成检查，保存回调可能耗时；随后直接发送订单，没有再次检查新暂停、信号、报价年龄和预算。新增四组离线测试分别在保存意图时暂停、改变报价、推进报价年龄和收紧预算，修复前均错误发送订单。现在复用完整计划检查，取消时将同一账本意图记为未发送的确定失败并释放风险预留，防止留下待查的虚构订单。
2. **利润归集网络等待后继续使用旧控制状态。** 暂停、在途委托及资金保留额/单批上限在早期检查，但行情查询可能耗时。新增八组测试覆盖划转前及已划转待购买两种状态下的四类变化，修复前均继续支出。现在在查询后及准备持久化划转/购买意图前检查最新配置和引擎状态，变更后等待重新评估。
3. **Windows 短暂文件占用导致账本保存失败。** 最终回归中多次观察到原子替换返回“拒绝访问”，失败位置随复测变化；未确定具体占用进程。原实现一次替换失败即退出。现在仅对共享冲突/拒绝访问执行有限的原子替换重试，最多额外等待 310 毫秒，持续失败仍报告错误并保留旧断点。新增原生句柄测试覆盖短暂占用释放后保存成功，以及持续占用时有界失败且旧止损状态不变。

这两组复现全部使用假交易客户端/HTTP 响应。修复前失败记录位于本地忽略目录 `build/verified/audit-143-probes.log`；新增断言已经纳入常规引擎与利润测试套件。

## 杠杆恢复复核

确认了设置超时后的查询先于重试；一轮最多两次设置与两次查询，明确参数/权限/限流拒绝不立即重试。只有同品种、目标倍数一致且查询完整成功才继续。空仓、中文符号、两种账户接口、冲突记录、错误/缺失字段、重试耗尽均有离线覆盖。确认后重新计算价格、止损与数量，最终检查仍保留信号、追价、时效、暂停、组合风险与换仓约束。失败不消耗入场 K 线，30 秒退避不影响已有仓位出场和保护止损。

## 依赖与无效代码清理

- 删除没有调用者的 `MainWindow::bot_cfg_path()` 及声明；不删除任何已有状态文件。
- 移除旧 `wsock32` 链接，保留 Windows 实际使用的 Winsock 2；不使用凭证存储的网络测试移除 `crypt32` 显式链接，GUI 和密钥测试继续保留。
- 删除未使用的 `<atomic>` 引入和已经删除的 ATR/旧策略接口注释，更新线程池生命周期说明。
- Qt Widgets、curl、simdjson 和 mbedcrypto 分别承担界面、HTTP/TLS、JSON及签名，均保留。手动 SAR/裸 K 仍有实际入口；研究脚本与源码工具不进入运行包。
- 将滞留的依赖清单版本和 README 当前版本统一到 v1.4.3；发布元数据工具增加版本一致性门禁。

## 验证与发布范围

本地 Windows 与 WSL Linux 使用 Release、`CCBOT_WERROR=ON` 构建并执行全部 CTest；补充执行套件覆盖、包布局及旧符号恢复检查。最终平台、架构、原生运行检查及 ASan/UBSan/TSan 结果随发布的 `BUILD_VERIFICATION.json` 提供，并核对产物来源提交和 SHA-256。

发布包保持：Windows GUI 及必要运行库、许可证和空 `data/`；macOS Intel/M 为 `TradingBot.app` 与空 `data/`；Linux x64/ARM64 仅无头程序和必要配置模板、说明、许可证。白名单、依赖闭包、内嵌版本、原生架构、空数据目录和泄漏检查均为发布门禁。

本次为源码调用链审查与离线回归，不是全路径形式化验证、依赖漏洞库全量扫描或真实交易所成交验收。历史成交、实盘配置和数据未被改写。
